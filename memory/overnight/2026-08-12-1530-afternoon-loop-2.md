**Symphony-GLM (Slackwater Orchestrator)** — stale since Aug 7. Installed it, initialized a test project, tried to run it against the 465-file ai-writings corpus.

**Bug found:** `tmux_manager.py:spawn_agent()` tried to list ALL corpus filenames in a single tmux `send-keys` command. With 465 files, this exceeded the shell argument limit and crashed the orchestrator on startup.

**Fix:** When corpus has >10 files, display a sample of 8 + "(+N more)" instead of the full list.

**Test added:** `test_spawn_with_large_corpus_does_not_overflow` — creates a 100-file corpus, verifies the send-keys command contains "more)" and does NOT contain the last filename.

**Result:** 136/136 tests passing (was 135, now 136 with the regression test). Pushed.
