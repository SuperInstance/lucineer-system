## Patterns & Surprises

### 🔍 The Overknowledge Problem
When Wesley already scores >0.85 on baseline, teaching consistently HURTS. Three clear examples tonight:
- Schema versioning: base 0.951 → taught 0.814 (Δ=-0.136)
- Vessel physics: base 0.882 → taught 0.674 (Δ=-0.208)
- D1 optimization: base 0.839 → taught 0.543 (Δ=-0.296)

**Recommendation:** Add a "baseline confidence gate" — if baseline > 0.85, skip teaching or switch to a refinement strategy instead of knowledge injection. Wesley doesn't need to be taught what he already knows.

### 🔍 Evaluator Failures
3 of 5 maritime iterations returned 0.000/0.000 — the evaluator (GLM-based similarity scoring) produced empty responses. Likely related to the API slowness — response truncation or timeout in the evaluation call. The evaluator needs a retry/fallback mechanism.

### 🔍 API Latency Crisis
Z.ai API averaged ~55 seconds per call tonight (normally <5s). Each iteration requires 3-4 API calls (teacher lesson, teacher evaluation x2, sometimes re-evaluation). This means:
- Each iteration: ~3-4 minutes
- Each domain (5 iterations): ~15-20 minutes
- Full overnight (4 domains): ~60-80 minutes

Normal overnight should be ~15-20 minutes total. Tonight took 3x longer.

### 🔍 Wesley's Strengths
- **Roblox/Luau** is clearly Wesley's strongest domain. Concrete, code-adjacent knowledge transfers well from teacher to student.
- **Abstract domains** (maritime economics, consistency models) are harder. The 2B model struggles to integrate abstract framing — it needs concrete patterns and examples.

### 🔍 Topic Pool Exhaustion
With only 8-10 topics per domain and daily runs, Wesley is seeing the same topics repeatedly. His baseline is improving on familiar topics (good!), but this reduces the measurable teaching delta (looks like regression). May need to expand topic pools or add topic variation.
