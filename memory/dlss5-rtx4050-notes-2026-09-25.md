# DLSS 5 on RTX 40 — notes for the RTX 4050 6GB laptop (WSL2, CUDA 13.4, driver 615.71.08)

Date: 2026-09-25. Research task on DLSS 5 Neural Rendering (NR) running on RTX 40-series GPUs,
focused on what our 4050 laptop can actually do.

## TL;DR

- **DLSS 5 NR official support is RTX 50-only today.** RTX 40 support has been announced
  ("planned", community reporting points to ~early 2027) but has not shipped in drivers.
- **The modding scene already runs DLSS 5 NR on Ada (RTX 40) via three paths:** a portable
  Windows app (Visual Enhancer), a bit-exact open-source Vulkan reimplementation
  (OpenDLSS-NR), and a WebGPU browser port (now `ports/browser-webgpu/` inside OpenDLSS-NR).
- **On our 4050/WSL2 box:** the realistic lane is Windows-host execution. WSL2 can't run the
  native Vulkan path (the required `VK_NV_*`/`VK_EXT_shader_float8` extensions don't pass
  through the DXG paravirtualization). WSL2 keeps its proven role: CUDA, NVENC/NVDEC.
- **Legal blocker on the big prize:** OpenDLSS-NR ships no weights; you must supply DLSS 5
  model data yourself (reported as extracted from a leaked DLSS 5 library). Don't build fleet
  infrastructure on leaked-weight extraction.

## 1. Merserk/dlss5-visual-enhancer — portable Windows enhancer app

URL: https://github.com/Merserk/dlss5-visual-enhancer

**What it is:** portable Windows 11 app ("Visual Enhancer.exe", download-and-run, no install)
for AI image/video enhancement. Its "Neuroframe Engine" wraps DLSS 5 Neural Rendering as one
stage in a configurable pipeline; no game injector needed.

**Pipeline stages (drag-reorderable, individually enable/disable):**
- Image: Denoising → DLSS Neural Rendering → Scaling → DLSS Super Resolution → RTX VSR →
  Coloring → Sharpening
- Video: same, plus DLSS Frame Generation and RTX Video HDR (SDR→HDR with tone controls)

**Notable capabilities:**
- NR controls: style (Default/Natural/Cinematic), intensity, 1–4 NR passes, local
  tone/structure strength, skin structure + auto-mask, custom NR mask, shimmer suppression.
- NR is NOT an upscaler (same-res in/out); separate Scaling stage (25%–200%) plus DLSS SR
  (DLAA/1.5×/1.72×/2×/3×, presets J–M) plus RTX VSR (quality 1–4, up to 4×/16384px).
- Live mode: NR applied during playback of local files, direct streams, YouTube, Twitch.
- Batch processing, preview clips (3–30s), 16-bit PNG/TIFF, ProRes/FFV1/H.264/H.265/AV1
  output with NVENC when available, separate GPU selection for AI vs NVENC.
- Inputs: common images, HEIC, RAW, nearly every video container.

**Requirements (verbatim from README):** 64-bit Windows 11 with Direct3D 12; NVIDIA RTX GPU
with current driver; DLSS 5 NR "availability depends on supported NVIDIA RTX hardware, the
installed driver, and successful feature initialization"; Frame Generation wants HAGS on;
RTX VSR/HDR need driver support.

**4050 verdict:** Runs on Windows host today for RTX VSR, DLSS SR, denoise, NIS sharpening,
NVENC encode. The DLSS 5 NR stage will almost certainly fail its "feature initialization"
check on a 4050 with current drivers (official support gate). Re-test when NVIDIA ships the
RTX 40 NR enablement. Community CUDA-binaries-swap mods reportedly force NR on RTX 40
(https://wccftech.com/modder-makes-nvidia-dlss-5-neural-rendering-work-on-geforce-rtx-40-series-through-a-simple-cuda-binaries-swap/)
— experiment territory, not fleet policy.

## 2. OpenDLSS-NR (maanHimself/OpenDLSS-NR) — open-source Vulkan reimplementation

URLs: https://github.com/maanHimself/OpenDLSS-NR · article:
https://wccftech.com/nvidia-dlss-5-gets-open-source-vulkan-reimplementation-runs-on-rtx-40-gpus-and-even-in-web-browsers/

**What it is:** MAAN's MIT-licensed Vulkan reimplementation of the DLSS 5 NR network — the
71-block Swin/ViT U-Net from DLSS-NR DLL build 310.8.0, with claimed **bit-exact** results
vs NVIDIA, including all 75 block-boundary intermediates (verified via a `parity` tool
against captured fixtures). This is fact, per the repo's own exactness contract
(docs/numerics.md); the bit-exactness claim is gated by tooling in-repo, which is stronger
evidence than typical modder claims. It is still one developer's verification suite.

**Architecture:** U-Net of shifted-window transformer blocks + global ViT at the bottom, FP8
(E4M3) activations with FP16 accumulation, ~141 MiB weights. Takes one rendered frame (LDR
proxy), three Gaussian-noise lanes, reprojected previous output, five conditioning scalars;
outputs RGB residual + temporal-blend logit. Generative NR, same-res in/out — NOT an
upscaler; DLSS-SR is explicitly not implemented. Temporal feedback lives in the demo.

**Two execution routes:**
- Native: GLSL compute kernels (reference, exact) + generated PTX kernels (`mma.sync` E4M3
  on tensor cores, cp.async rings, split-K GEMMs) — the fast path.
- WebGPU: independent port at `ports/browser-webgpu/`, same network bit-exact against the
  same captures, no tensor cores, no FP8, no inter-block fusion.

**Performance (RTX 4070 SUPER, min over 40 frames, 241 dispatches/frame):**
768²: 2.8 ms · 1080p: 7.8 ms · 1440p: 12.6 ms · 4K: 29.3 ms. WebGPU: 72 ms @ 512² vs 2.7 ms
native. So Ada tensor cores make this genuinely realtime-capable.

**Exact requirements (from README):**
- Windows, NVIDIA **Ada (RTX 40) or newer** GPU, driver exposing `VK_KHR_cooperative_matrix`,
  `VK_NV_cooperative_matrix2`, `VK_EXT_shader_float8`, `VK_NV_cuda_kernel_launch`.
- VS2022, Python 3, Node+npm; portable toolchain downloaded by scripts (no Vulkan SDK needed).
- **You supply the weights** as a model directory (manifest.json + packed E4M3 stage files).
  "Nothing in this repository produces such a directory." Repo contains no NVIDIA software or
  weights; press coverage reports weights circulating from a leaked DLSS 5 library.

**4050 verdict:** Hardware-qualified in principle (Ada, 4th-gen tensor cores with FP8, 141
MiB weights fit trivially in 6GB). Realistically: **Windows host only** — the PTX route needs
`VK_NV_cuda_kernel_launch` + `VK_EXT_shader_float8`, which exist in the Windows NVIDIA ICD;
WSL2's Vulkan goes through Mesa d3d12/dzn over /dev/dxg and won't expose those NV extensions.
No display needed for the `dlss5vk bench/profile/parity` CLI (compute-only), but still needs
the Windows driver's Vulkan. Display required for the Filament demo. The weights problem is
yours to solve and legally radioactive.

## 3. WebGPU browser port (digitalcitizen.life article)

URL: https://www.digitalcitizen.life/modder-gets-dlss-5-running-in-a-web-browser-through-webgpu/
(fetched via search summary; direct fetch 403'd — Cloudflare. Corroborated by Tom's Hardware:
https://www.tomshardware.com/pc-components/gpus/modder-gets-nvidias-dlss-5-working-in-a-web-browser-using-webgpu-147mb-browser-port-runs-on-non-nvidia-gpus-and-macos-but-takes-two-seconds-per-render)

**Facts:** MAAN ported the DLSS 5 NR network to WebGPU compute shaders, bypassing NGX and
Streamline entirely. ~147 MB model, ~1 MB compressed JS runtime. Runs in browsers on
non-NVIDIA GPUs and macOS. ~1–2 s per rendered frame on an RTX 40 desktop — offline-quality,
not realtime. Live demo with prepared 3D scenes + model upload existed; "source coming to
GitHub" has since landed as `ports/browser-webgpu/` in OpenDLSS-NR (repo confirms: same
network, bit-exact vs same captures, 72 ms @ 512²).

**Hype vs fact:** "DLSS 5 in a browser" is real and verified bit-exact, but it's seconds-per-
frame NR enhancement of one rendered frame — not game upscaling, not realtime, and it still
needs the ~147 MB of weights fetched by the page (same provenance question).

**4050 verdict:** Works today in a browser **on the Windows host** (Chrome/Edge WebGPU).
Pointless to attempt inside WSL2 (no browser/display; WSLg software paths would negate it).
6GB VRAM is fine for 512–1080p-class inputs.

## 4. RTX 4050 laptop 6GB / WSL2 feasibility matrix

| Capability | Where it runs | Today? | Notes |
|---|---|---|---|
| RTX Video Super Resolution / Video HDR | Windows host (driver-level; app/players) | YES | Officially supported on RTX 40; real fleet value now |
| DLSS Super Resolution offline (NGX SDK) | Windows host; WSL2 unlikely (NGX needs DX/VK display stack) | YES | RTX 40 officially supported |
| Visual Enhancer app (VSR/SR/denoise/NVENC stages) | Windows 11 host | YES | NR stage blocked until official RTX 40 enable |
| DLSS 5 NR via Visual Enhancer / official NGX | Windows host | NO (yet) | RTX 50-only driver gate; RTX 40 support announced, not shipped |
| OpenDLSS-NR native (Vulkan+PTX, tensor cores) | Windows host | YES, hardware-qualified | Blocked by weights supply + legality; CLI is headless but still Windows Vulkan |
| OpenDLSS-NR in WSL2 | — | NO | Required VK_NV_cuda_kernel_launch / VK_EXT_shader_float8 don't survive DXG paravirtualization |
| WebGPU browser port | Windows host browser | YES | 1–2 s/frame; offline only |
| CUDA + FP8 tensor cores | WSL2 | YES | Our proven lane (CUDA 13.4); FP8 E4M3 available on Ada via torch/cutlass |
| NVENC/NVDEC | WSL2 | YES | ffmpeg nvenc/nvdec work in WSL2; Ada has AV1 encode |

WSL2 specifics: default WSL2 has no display server (WSLg aside); anything needing swapchains
or a browser belongs on Windows. Headless Vulkan compute in WSL2 is possible only through
dzn/d3d12 — fine for portable VK, dead-end for NVIDIA-proprietary extensions.

## 5. Usable TODAY vs aspirational

**Today (RTX 4050):**
- RTX VSR + Video HDR batch/enhance on Windows host; DLSS SR offline on RTX 40 (official).
- NVENC (incl. AV1) + NVDEC pipelines in WSL2 via ffmpeg — the fleet video backbone.
- FP8 tensor-core compute in WSL2 CUDA for our own neural-imaging (Real-ESRGAN-class
  restorers, etc.) — same math class as DLSS NR without NVIDIA's model.
- WebGPU demo experiments on any fleet machine with a browser.

**Aspirational / watch:**
- Official DLSS 5 NR on RTX 40 (driver update, ~2027 per reporting) → then Visual Enhancer's
  NR stage likely lights up on the 4050 with zero modding.
- OpenDLSS-NR as a headless batch NR pipeline (it's architecturally ideal: CLI, fixtures,
  parity gates) — blocked solely on weights legitimacy. If NVIDIA ever open-licenses NR
  weights, this repo is the integration path.
- OptiScaler-style overhead reductions for in-game NR (wccftech reports a cost-halving mod).

## 6. Fleet implications (low-level GPU harnessing)

- **Media archive restoration:** Don't wait for DLSS 5. The boring stack (RTX VSR on Windows
  nodes + NVENC/NVDEC in WSL2 + FP8 tensor-core open models in CUDA) covers upscale/restore
  workloads today across every 40-series box. DLSS 5 NR becomes a quality multiplier only
  after official RTX 40 enablement, and Visual Enhancer-style apps are then the no-code path.
- **Architecture lesson from OpenDLSS-NR:** the valuable pattern isn't DLSS 5 itself — it's
  one dev showing a 71-block FP8 Swin/ViT running realtime on Ada via hand-generated PTX +
  cooperative matrices, with a bit-exactness harness. That's a template for fleet-side
  custom NR/restore kernels on our existing GPUs (CUDA graph + FP8, or torch.compile paths).
- **WebGPU as a compute side-channel:** any machine with a browser becomes a worker for
  non-realtime media enhancement with zero install and zero CUDA dependency (macOS, AMD/Intel
  boxes). 1–2 s/frame is fine for archive jobs. Watch ONNX-Web/WebGPU inference maturing.
- **Weight legality is an infra constraint:** anything built on leaked DLSS 5 weights is
  unusable for fleet work. Keep DLSS 5 as consumer-app magic (run it inside supported apps on
  Windows); build fleet neural imaging on open-licensed models.
- **4050 6GB is adequate** for all of the above: NR network ~141 MiB weights; VSR/DLSS SR
  well within budget; NVENC runs alongside. Constraint is Windows-vs-WSL split, not VRAM.
