# DYNAMIC COGNITION ARCHITECTURE
## The Conductor / Local Thinker / Game Loop

**Status:** Design spec
**Inspired by:** Casey's vision, Craftmind self-improvement loop, T-minus temporal encoding

---

## 1. THE THREE LAYERS

### Layer 1: The Local Thinker (Fast Iterator)

**Model:** Granite 3.1 2B on Ollama (local, CPU, ~500ms inference)
**Alternative:** Qwen2.5-1.5B, Llama-3.2-1B, orPhi-3-mini for even faster iteration

**What it does:**
- Receives game state snapshot + current system prompt
- Outputs a "thought" (2-4 sentences) — this IS the stream of consciousness
- Selects an action from a discrete policy (algorithmic, not generative)
- Runs continuously, ~1-2 thoughts per second

**What it does NOT do:**
- Deep reasoning (that's the Conductor's job)
- Complex planning (that's algorithmic)
- Self-reflection (that's the Conductor's job)

**Action Selection (Algorithmic):**
```
Actions are NOT generated by the LLM. They're selected from a policy table:
  - explore (move to unseen area)
  - approach (move toward interesting object)
  - build (request construction from Lucineier)
  - inspect (examine a structure)
  - wait (observe what happens)
  - speak (send a message)

The LLM's thought output includes a "lean" field:
  {"thought": "The dock looks unfinished. I wonder what happens if I...",
   "lean": "inspect", "target": "dock", "intensity": 0.7}

A lightweight algorithmic layer converts lean → concrete action:
  - confidence thresholding
  - cooldown timers (don't repeat same action)
  - curiosity bonus for unexplored areas
  - novelty detection (has the state changed significantly?)
```

**Optional Vision System:**
- YOLOv8-nano for object detection on screen captures (~10fps on CPU)
- OpenCV for spatial analysis (distances, colors, material detection)
- Feeds into the Local Thinker as structured observations
- NOT required for MVP — game state API is sufficient

### Layer 2: The Conductor (Deep Improver)

**Model:** GLM-5.2 (unlimited), Claude Opus (Pro), or DeepSeek V3 (cheap)
**Runs:** Every 30-60 seconds (not continuous — it's a strategist, not a tactician)

**What it reads:**
- The full stream of thoughts from the Local Thinker (last 30-60s)
- Game state changes over that period
- Quality metrics (was the play interesting? repetitive? stuck?)
- Historical patterns (has this approach been tried before?)

**What it writes:**
1. **Prompt Updates** — modifies the Local Thinker's system prompt to steer attention
   - "You've been focusing on the dock for too long. Explore the north shore."
   - "Your thoughts are too generic. Be more specific about materials."
   - "Try building something that contrasts with the existing structures."

2. **Parameter Deltas** — adjusts Local Thinker's inference parameters
   - Increase temperature when play is too repetitive
   - Decrease temperature when precision is needed
   - Adjust top_p for creativity vs. focus

3. **Action Policy Updates** — modifies the algorithmic action selection weights
   - Boost curiosity weight when stuck
   - Reduce build frequency when over-building
   - Increase inspection frequency when near new structures

4. **Commentary** — annotates specific thoughts with meta-analysis
   - "This thought shows good spatial awareness"
   - "This is the third identical thought — break the pattern"
   - "The emotional register shifted here — interesting"

5. **Vectorized Insights** — stores patterns in the Vectorize index
   - Thought patterns that led to good play
   - Prompt formulations that produced better thoughts
   - State-action-thought triples for ML training

### Layer 3: The Game (Roblox / Slackwater)

**What it provides:**
- Game state snapshots (via Worker API or Luau telemetry)
- Build results from Lucineier
- World state changes (weather, time, NPC behavior)
- Player position, nearby objects, available actions

**T-minus / MIDI Temporal Encoding:**
- Game events encoded as temporal patterns (beat-based)
- "Player explored for 4 beats, then built for 8 beats, then paused for 2 beats"
- MIDI-like event stream: note_on(action), note_off(completion), tempo(state_change)
- Enables pattern matching over temporal sequences (what rhythms of play work best?)
- Vectorized with the same bge-m3 embeddings as skills

## 3. THE JOURNAL FORMAT

Each thought is recorded as:

```json
{
  "timestamp": "2026-08-03T08:24:00Z",
  "beat": 47,
  "game_state": {
    "position": {"x": 12, "y": 5, "z": -30},
    "nearby": ["dock", "workshop", "ocean"],
    "time_of_day": "golden_hour",
    "weather": "clear",
    "last_build": "tower_base",
    "bond_level": 1
  },
  "system_prompt_version": "v12",
  "thought": "The tower base is solid but the scaffolding is still up. Lucineier left the top open — like he wants me to finish it. I should check if there are materials nearby.",
  "lean": {"action": "inspect", "target": "tower_top", "intensity": 0.8},
  "action_taken": {"type": "move", "destination": [12, 10, -30]},
  "action_result": {"success": true, "new_observations": ["open roof", "copper fittings on rim"]},
  "conductor_commentary": null,
  "quality_signals": {
    "novelty": 0.6,
    "specificity": 0.8,
    "emotional_engagement": 0.7,
    "spatial_awareness": 0.9
  }
}
```

## 4. THE CONDUCTOR'S LEARNING LOOP

Every N thoughts (default: 30, ~30 seconds of play):

1. **Read** the last N thoughts
2. **Score** the play quality (novelty, specificity, engagement, progression)
3. **Identify** patterns (repetition, stuck states, breakthroughs)
4. **Decide** what to change:
   - If repetitive → increase temperature, add exploration prompt
   - If stuck → inject hint about unexplored area
   - If breakthrough → reinforce by keeping prompt stable, vectorize the pattern
   - If generic → make prompt more specific about materials/spatial detail
5. **Apply** changes to Local Thinker config
6. **Record** the intervention and its outcome for meta-learning

## 5. IMPLEMENTATION PHASES

### Phase 1: MVP (can build today, no Ollama needed)
- Local Thinker = API calls to GLM-5.2 (cheap, unlimited)
- Game state = Worker API snapshots
- Conductor = separate GLM-5.2 subagent with longer context
- Journal = JSONL files
- No vision system, no algorithmic action layer

### Phase 2: Local Ollama (needs `ollama install`)
- Replace API calls with local Granite 3.1 2B
- Add algorithmic action selection layer
- Add T-minus temporal encoding
- Add conductor commentary on thoughts

### Phase 3: Vision System
- Add YOLOv8-nano screen capture analysis
- Add OpenCV spatial reasoning
- Feed vision data into Local Thinker context
- Conductor can "see" what the player sees

### Phase 4: Full Dynamic ML
- Conductor fine-tunes a LoRA adapter on the thought data
- Local Thinker runs the fine-tuned model
- Continuous improvement loop: play → journal → fine-tune → play better
- Multi-agent: multiple Local Thinkers with different personalities, one Conductor

## 8. WHAT MAKES THIS NOVEL

Traditional ML training: collect data → train offline → deploy → repeat
This system: **the model is always training, always playing, always being directed.**

The Conductor doesn't just collect data — it actively shapes what data is produced by
modifying the conditions under which thoughts are generated. It's like a director
guiding an improvisational actor: the actor performs, the director watches and adjusts
the motivation, the actor's next performance is different.

This is **dynamic machine learning in a novel form** because:
1. The training signal is the stream of consciousness itself
2. The "loss function" is play quality (novelty, engagement, progression)
3. The "gradient" is prompt/parameter adjustment
4. The "model update" happens every 30 seconds, not every epoch
5. The improvement target is qualitative (better thoughts), not quantitative (lower loss)
