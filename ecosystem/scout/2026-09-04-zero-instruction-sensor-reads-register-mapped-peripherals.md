# Zero-Instruction Sensor Reads — Register-Mapped Peripherals on a Soft Processor

**What:** arXiv:2608.05638 (cs.AR/eess.SY, Aug 2026). Case study in application-driven specialization of a five-stage 32-bit RISC soft processor (MIPS tradition), on a reaction-wheel self-balancing bicycle control loop. Two moves: (1) **register-mapped peripherals** — two frequently-read sensor inputs are mapped directly into architectural register state, written every cycle by hardware and owned via the register file's write-port structure rather than bus arbitration; reading them costs **no dedicated instruction and no cycle** — they fold into arithmetic that executes anyway (memory-mapped equivalent costs 5 extra instructions per snapshot). (2) **Hardware-offloaded PWM** — four periodic channels driven continuously from four exported registers, removing waveform maintenance from software. Control loop drops 91→43 cycles. Notably honest negative: the deadline was met by 7,300–15,000× margin either way — "the specialization was not necessary for real-time compliance; its value lies in instruction count and software simplicity, not in determinism, which an on-chip single-cycle I/O region already provides."

**Why it matters to us (quilt-verilog chip-fleshing + Boat lane):**

- **The fabric already speaks this dialect.** Per-cell state exported as live registers read by the tick scheduler, dial-13 live echo-gate, op-buses read combinationally — the paper gives the pattern a name and a measured cost model (zero-cycle reads via register-file write-port ownership vs arbitration). When fleshing out q_view/q_tick interfaces, register-mapping frequently-sampled cell state (occupancy, egress counts) beats memory-mapped reads by exactly their 5-instructions-per-snapshot delta.
- **Write-port ownership, not arbitration** is a clean structural answer to the F3/ring contention class: hardware owns specific registers outright, so there is no arbitration path to wedge. Worth checking whether the fabric's net-vs-occ anomaly lanes (#1a) could adopt exclusive-ownership registers for hot counters.
- **Boat lane:** NMEA sensors + engine telemetry as register-mapped inputs on the boat brain is the natural extension — AIS/engine data folding into the supervision loop without a bus transaction each read.
- **The honest negative is a Tapestry-doctrine exemplar:** specialization bought simplicity, not determinism — worth citing when we decide how much hardware to grow vs staying software-defined. Their two-configuration disclosure (archived build lacking the multiplier) is also our provenance-honesty style.
