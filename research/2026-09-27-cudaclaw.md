# cudaclaw — spec draft (2026-09-27)

*Context: always-on local orchestrator ("Tom Sawyer" GPU-handler) recruiting compute workers on RTX 4050 6GB (CUDA 13.4 via /dev/dxg, WSL2, Ryzen AI 9 HX 370), coordinating with algorithm bots on other local chips and subagents in idle lanes. Follows fleet conventions: honest append-only receipts, fixed seed 2718, O(chunk) memory, ext4 for state, no shell-string subprocess.*

## (a) What a cudaclaw IS

A cudaclaw is a **packaged, invocable GPU worker with a declared cost envelope** — not a daemon, not a service. Concretely, a directory under `claws/`:

1. `kernel.cu` + `build.sh` (source-of-truth) and/or a prebuilt `.so`/cubin with a flat C ABI;
2. `claw.json` — manifest: name, version, ABI, **declared VRAM ceiling (bytes)**, duration class (µs/ms/s), input/output schema, determinism policy (seed 2718 default), cancel-poll interval;
3. runner contract: reads a JSON job descriptor on stdin, writes one JSON receipt to stdout, defined exit codes.

One process per job. Crash = clean failure; absent receipt = job never happened. That honesty is the load-bearing property.

## (b) Discovery, recruitment, scheduling, preemption

- **Discovery:** orchestrator scans `claws/*/claw.json`. Self-describing, no central registration.
- **Recruitment:** first contact = a calibration probe (tiny N run); measured VRAM/time is recorded beside declared values in the ledger. Declared vs measured both kept forever — drift is a signal.
- **Scheduling:** one flat SQLite job queue on ext4 (jobs: id, claw, args, state, priority, submitted_by). The GPU-handler pops jobs whose declared+measured VRAM fits current headroom. Default policy on 6GB: one heavy job; small jobs may co-reside below ~80% of 6GB.
- **IPC:** boring on purpose — stdin/stdout JSON + exit codes. No sockets or shm in v1.
- **Preemption:** cooperative. Claws check a cancel file (and handle SIGTERM) at chunk boundaries, exiting with `{"status":"preempted","progress":x}` + partial receipt. Ignored SIGTERM past a deadline → SIGKILL, and the ledger records a "dishonest death."
- **Receipts:** every run appends JSONL — job id, claw name+version, seed, start/end, peak VRAM, temp, throughput, output hash, verdict. Written on failure too; never edited.

## (c) Throttle contract

Long-running claws emit a heartbeat line to **stderr** every ≤2s (stdout stays clean for the final receipt): `{vram_mb, gpu_temp_c, util_pct, items_per_sec, progress, phase}`. Throttling is via a control file `job.<id>.throttle` (0..1) that claws read at chunk boundaries — the orchestrator ramps down by writing lower values (or `pause`), ramps up by restoring 1.0. VRAM via cuMemGetInfo/torch, temp via NVML; both **gracefully optional** (WSL2 NVML is quirky) — if missing, claw reports `"telemetry":"degraded"` and the orchestrator schedules conservatively. Contract rule: no chunk boundary may exceed ~2s of unthrottleable work.

## (d) Minimal first cudaclaw

- **claw-00 `selftest`** (~50 lines): device probe + device-to-device memcpy bandwidth + a deterministic FLOP loop at seed 2718. It does almost nothing *except* validate the entire recruit→run→receipt→preempt loop before any real kernel risks it. Cheap, unblockable, and it produces the first measured receipts.
- **claw-01 `correlate-cuda`:** port the inner loop of the existing `tools/correlate.py` (already pure-stdlib, O(chunk), seed 2718 — the D13/D18 fan-out synthesis primitive) to CUDA: chunked float32 correlation/dot-products. Real fleet work, trivially verifiable against the CPU reference, naturally chunked. Success = matches CPU within float tolerance at seed 2718 and reports the *honest* speedup — which may be ≈1× at small N (PCIe transfer dominates). That honesty is the point.

## Open questions

- Co-residency accounting when claws under-report VRAM (OOM kills) — suggest a "VRAM trust score" in the ledger.
- Whether algorithm bots on other chips (NPU/iGPU) speak the same claw.json manifest or a sibling format ("npuclaw"?).
